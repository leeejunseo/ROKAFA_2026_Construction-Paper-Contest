# 하이브리드 3종 비교 확장 — 실험 설계안

작성 배경: 기존 dfxai 실험(README, 2026-09-15)은 하이브리드를 "선형 혼합"(α 고정 평균) 한 종류와 통제조건 "Shield"(감독형)만 갖고 있었고, 둘 다 성능·설명가능성 트레이드오프에서 절충점이 아니었다는 결론이었다. 여기에 "잔차형(residual)"과 "진짜 게이팅형(학습된 혼합 비율)"을 새로 추가해서, 하이브리드 설계 방식 자체를 변수로 놓고 트레이드오프 지도를 그리는 게 목표다. 2026-10-08 논문 제출까지 약 2주 남은 상태에서 착수하는 설계이므로, 완성도보다 "제 시간에 끝나는 것"을 최우선으로 잡았다.

> **결과 (2026-09-29).** 두 계열 모두 절충점이 아니었다. 잔차형 200세대 0.628(BT-v2 를 넘지 못함, D\* 6/17/6),
> 게이팅형 200세대 0.722(순수 학습에 근접, D\* 17/17/17, 게이트가 고정 비율로 수렴). 자세한 표는 README 6.10절.
>
> **구현 상태 (2026-09-23).** 이 설계안은 같은 날 구현되어 학습이 시작됐다. 실제 파일명과
> 설정은 README 3.6절을 따른다(설계안의 가칭 파일 두 개는 `rl/train_es_hybrid.py` 하나로
> 합쳤고, 잔차형 β=0.35, 두 계열 모두 200세대·3시드). 결과는 README 6.10절에 채운다.

## 1. 지금 상태 정리

| 이름 | 방식 | 상태 |
|---|---|---|
| 순수 BT | 규칙 트리 | 완료 (BT-v1/v2/v3) |
| 순수 RL | ES, BT 복제 초기화 | 완료 (20시드) |
| 선형 혼합 | a = (1−α)·BT + α·RL, α 고정 | 완료 |
| Shield (감독형) | 안전 조건이면 BT 안전 노드, 아니면 RL(+G 상한) | 완료 — 이미 "규칙 기반 게이팅"에 가까운 조건으로 재활용 가능 |
| **잔차형** | 신규 | 완료 (3시드, README 6.10) |
| **게이팅형(학습형)** | 신규 | 완료 (3시드, README 6.10) |

Shield는 "규칙이 스위치를 켜고 끄는" 방식이라 게이팅의 한 종류로 볼 수 있지만, 사용자가 원하는 건 "언제 BT를 더 따르고 언제 RL을 더 따를지를 정책이 스스로 학습하는" 진짜 게이팅이므로 별개로 새로 만든다.

## 2. 잔차형(Residual) 설계

**핵심 아이디어**: RL이 완전히 독립적인 지령을 내는 게 아니라, BT-v2의 지령에 더할 "작은 보정치"만 낸다.

```
a_final = clip(a_BT-v2 + β · a_RL_delta, 행동한계)
```

- `a_RL_delta` ∈ [-1, 1]³ (network output, tanh)
- `β`는 보정 허용폭을 정하는 고정 스칼라. 처음엔 β=0.3~0.4 정도로 시작 — RL이 BT를 완전히 뒤집을 수 없고 "다듬는" 수준만 가능하게 제한. β는 하나의 설계 변수라 나중에 스윕할 수도 있지만, 시간이 없으면 값 하나로 고정하고 그 근거만 방법 절에 한 줄 적는다. **→ β=0.35 로 고정.** 정규화 단위에서 0.35 는 뱅크 최대 ±63°, 하중배수 최대 ±1.6 G, 스로틀 최대 ±17.5% 의 보정에 해당한다.
- 네트워크 구조: 기존 RL과 동일한 20-32-32-3 MLP. 초기화는 **가중치를 0에 가깝게(작은 분산) 초기화**해서 학습 시작 시점엔 delta ≈ 0, 즉 거의 순수 BT처럼 행동하다가 점점 보정을 배우도록 한다. (기존 BT 복제 초기화보다 오히려 더 간단 — 처음부터 "BT와 다르지 않음"에서 출발.) **→ 표준편차 0.01 로 초기화, 1세대 |δ| 평균 0.011.**
- 적합도 함수: 기존 RL과 동일한 것을 그대로 쓴다. 필요하면 `−λ·|delta|` 항을 아주 약하게 추가해 "꼭 필요한 만큼만 보정"하도록 유도할 수 있지만, 이것도 시간이 없으면 생략 가능(1차는 기존 적합도 그대로 돌려보고, 붕괴하거나 이상하면 그때 추가). **→ 1차는 기존 적합도 그대로.**
- 학습: 기존 ES 파이프라인 그대로 재사용하되 **정책 클래스만 residual 방식으로 교체**. 상대는 기존과 동일하게 BT-v1/v2 교대. 뱅크 채널은 각도이므로 더한 뒤 clip 하지 않고 ±180° 에서 원형으로 감는다(clip 하면 −180° 근처에서 불연속).

## 3. 게이팅형(학습된 혼합 비율) 설계

**핵심 아이디어**: 고정 α가 아니라, 상황(관측)에 따라 "지금은 BT를 몇 %, RL을 몇 % 반영할지"를 정책이 스스로 정한다.

```
a_final = (1−g(o))·a_BT + g(o)·a_RL     (뱅크 채널은 기존처럼 원형 평균)
g(o) = sigmoid(gate_net(o)) ∈ [0, 1]
```

**시간을 아끼는 핵심 결정: RL 절반은 새로 학습하지 않고 기존 체크포인트를 재사용한다.**

- `a_RL`은 이미 학습된 순수 RL 정책(300세대, 대표 시드 하나 또는 소수) 체크포인트를 그대로 가져다 쓴다. **→ 학습 시드 11 의 300세대 체크포인트 하나로 고정.** 근거: '치고 빠지기' 군집(20개 중 16개)의 대표이고, 점수 0.776(20개 중 2위)·D\*=3 으로 성능과 설명가능성이 둘 다 좋은 정책이다. 게이트가 여기서 무엇을 더 얻는지(또는 잃는지)가 가장 선명하게 드러난다.
- 새로 학습하는 건 작은 게이트 네트워크(`gate_net`) 하나뿐: 20-8-1 정도의 아주 작은 MLP(177개 파라미터). 입력은 동일한 20차원 관측. 초기 가중치는 표준편차 0.05 로 g ≈ 0.5(선형 혼합 α=0.5 와 같은 출발점).
- ES로 게이트 네트워크만 최적화. 적합도는 기존과 동일.
- 이렇게 하면 "RL 정책 자체를 처음부터 다시 학습"하는 리스크(README 9절에 기록된 보상 해킹, ES 붕괴 같은 실패들)를 피하고, 새로 디버깅해야 할 대상을 게이트 하나로 좁힐 수 있다.

이 설계는 Shield(규칙이 스위치)와 대비된다: Shield는 "안전 조건이면 무조건 BT", 게이팅은 "상황을 보고 정책이 알아서 비율을 조절"이라 대비가 뚜렷하고 논문에서 설명하기도 좋다.

## 4. 평가 계획 (축소판)

시간이 없으므로 기존 본실험(20시드)만큼은 무리다. 아래 수준을 제안한다.

- **학습 시드**: 잔차형·게이팅형 각 3~5개 (계획서에 이미 "RL 학습 시드 3개"로 써놓은 전례가 있어 방어하기 쉬움) **→ 각 3개(시드 0·1·2)**
- **평가**: 기존과 동일하게 BT-v2·BT-v3 상대, 각 100시드 × 진영 교대 2 = 400교전/정책. 예산 축은 100·200세대 체크포인트.
- **지표**: 기존 파이프라인 그대로(점수·순수승률·D\*·F(4)·위반율) — 대리모델 분석 코드는 정책 종류를 안 타므로 그대로 재사용 가능
- **통계**: 기존과 같은 틀(시드 단위 대응비교, Holm 보정)에 조건만 6개(BT-v2 대표, 순수RL 대표, 선형혼합 대표 α, Shield, 잔차형, 게이팅형)로 확장

## 5. 논문에 넣을 그림 — 트레이드오프 지도

x축 = D\*(설명가능성, 작을수록 쉬움), y축 = 점수(성능). (실제로 생성된 그림 `fig_tradeoff_families.png` 는 축이 반대라 가로가 점수, 세로가 D\* 이고 좋은 영역은 **오른쪽 아래**다. 아래 "왼쪽 위"는 이 절의 축 기준이다.) 6개 조건을 점으로 찍는다. 사용자가 제안한 내러티브를 그대로 시각화:

- 오른쪽 아래(성능↓ 설명↓ 둘 다 나쁨) — 아마 선형혼합
- 오른쪽 위(성능↑ 설명↓, 즉 통념과 정반대인 순수 RL) — 기존 결과
- 왼쪽 위(성능↑ 설명↑, 둘 다 좋음) — 잔차형이나 게이팅형이 여기 온다면 논문의 핵심 그림이 됨
- 어느 한쪽만 좋은 나머지 — Shield(설명은 나쁘지만 위반율 0이라는 별도 장점 병기)

`fig_tradeoff_families.png`를 확장하는 형태로 만들면 기존 파이프라인과 자연스럽게 이어진다(`analysis/figures.py` 에 두 계열의 마커를 이미 추가했다).

## 7. 지금 환경에서의 실현 가능성 검토

먼저 전제: 이 검토는 실제로 코드를 돌려본 게 아니라 README에 적힌 스펙(의존성·하드웨어·기존 코드 구조)을 근거로 한 서면 검토였다. 같은 날 실제 구현으로 확인된 사항은 굵게 덧붙였다.

**의존성 — 문제 없음.** 잔차형·게이팅형 둘 다 기존과 같은 numpy 기반 MLP 순전파만 쓰면 되므로 새 라이브러리 설치가 필요 없다. torch(BC 초기화용)·gymnasium/SB3(PPO용)는 둘 다 건드릴 필요 없음. GPU도 필요 없다. **확인됨.**

**"ES 루프 재사용" 자체가 이미 검증된 패턴.** BTO가 좋은 선례다. BTO는 1,827개짜리 신경망이 아니라 상수 9개만 같은 ES 루프·같은 적합도로 최적화했고 실제로 잘 돌아갔다. **같은 방식으로 `train_es_hybrid.py` 를 만들었고 2세대 시험 실행과 run_eval 연결까지 통과했다.**

**계산 시간 — 잔차형은 기존 RL과 비슷, 게이팅형은 "더 빠를 것"이라는 가정을 수정해야 한다.** ES 한 세대의 시간을 잡아먹는 건 신경망 계산이 아니라 **교전 시뮬레이션 롤아웃**(개체군 32 × 후보당 8교전)이라서, 파라미터가 적다고 세대당 시간이 크게 줄지는 않는다. 다만 탐색공간이 작아 더 적은 세대 수로 수렴할 가능성은 있다. **실측: 두 계열 모두 세대당 약 13초(워커 10, 수용 검사 포함), 200세대 ≈ 45분.** 게이팅형은 여기에 학습 정책 순전파가 한 번 더 들어가 오히려 약간 느리다.

**세대 수를 줄이는 것 자체의 근거.** 기존 예산 스윕 표(README 6.1절)를 보면 100세대에서 이미 점수 0.646, 300세대에서 0.716로 절대적 차이는 크지 않다(위반율·D\*는 오히려 100~300 사이에서 거의 평평). 그래서 새 두 조건은 **200세대**로 잘랐다.

**남아있는 실질적 위험.**
- 잔차형: β가 너무 작으면 RL이 사실상 아무것도 안 배우고(BT와 구별 안 됨), 너무 크면 선형혼합과 다를 바 없어진다. 학습기가 매 세대 |δ| 평균·표준편차를 history 에 기록하므로 25세대 체크포인트에서 바로 확인한다.
- 게이팅형: 게이트가 학습 중 0 또는 1로 붕괴해서 사실상 "순수 BT" 또는 "순수 RL"과 같아질 위험이 있다. 학습기가 g 의 평균·표준편차를 기록한다. 표준편차가 0 에 붙으면 붕괴다.
- 두 위험 모두 "학습 자체가 안 되는" 문제라기보다 "학습은 되는데 의도한 대로 안 되는" 문제라서, 결과 해석 단계에서 뒤늦게 발견될 수 있다. 그래서 진단값을 학습 로그에 넣어 학습 중에 보이게 했다.

**결론.** 소프트웨어·의존성 관점에서는 막히는 게 없었고, 구조적으로도 BTO라는 성공 선례가 있어 실현 가능성은 높다고 봤으며 실제로 하루 안에 구현·시험·학습 착수까지 끝났다. 실제 병목은 시뮬레이션 롤아웃 시간과 하드웨어의 전력 제한이다.
