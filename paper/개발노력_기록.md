# 개발 노력 기록

"BT 와 RL 에 들인 노력이 다르지 않느냐"는 지적은 반드시 나옵니다. 완벽히 공평할 수는
없지만, **기록해서 밝히는 것**과 침묵하는 것은 심사에서 천지 차이입니다. 아래 표를
채워 논문 논의 절(반론 대응)과 부록에 인용하십시오.

자동 수집되는 값은 `paper/results_auto.md` 표 M1(복잡도)·M2(학습 시간)에 있습니다.
사람 시간은 직접 기록해야 합니다. 대략적이어도 좋으니 **비워 두지 마십시오.**

## 튜닝 이력 (정직하게)

시도했다가 버린 것을 적으십시오. 논문에는 "X 를 시도했으나 Y 때문에 채택하지
않았다"로 한 줄씩 들어갑니다. 예:

* BT: 뱅크 지령 한계 ±100° → ±180° (행동 포화로 대리모델이 깊이 1에서 R²=0.98 달성하는 함정, README 5.4)
* 지표: 충실도 단순 평균 → 분산가중 평균 (상수 채널 부풀림 제거)
* 평가: 단일 진영 평가 → 진영 교대 짝지은 설계 (자기대전 0.59 → 0.500)
* BT: 정면 합류 회피 노드 추가 (충돌 무승부 45~53% → 3~10%; README 5.2)
* ES/셰이핑: 1차 적합도 → 원거리 회피 정책으로 수렴(보상 해킹) → 근접 가중·교전 지표
  비중 확대·소극 무승부 벌점으로 재설계 (README 5.5, shaping.py 설계 이력)
* ES: α 커리큘럼 → 고정 격자 (후반 α≥0.9 만 학습되어 α=0.25 정책이 미학습 상태였음)

## 논문에 들어갈 문장 (초안)

> 본 연구의 규칙 기반 모델과 학습 기반 모델은 동일한 팀이 제한된 예산 내에서 구현한
> 것으로, 설계·구현·튜닝에 각각 약 __시간과 __시간을 투입하였다(부록 __). 따라서 두
> 계열의 절대적 성능 순위는 일반화할 수 없으며, 본 연구의 주장은 성능 순위가 아니라
> 성능–설명가능성 관계의 형태에 있다.
