## 2. E3: 6DOF 과G 위반율이 BT-v3 에서 0.393 이던 이유

**원인.** BT-v3 는 "가용 G 의 8/9"를 지령하므로 고속에서는 정확히 8.0 G 를 지령한다(BT-v3 적분 스텝의 92%).
3DOF 의 기체 하중은 지령을 1차 지연으로 아래에서 따라가 8.0 G 를 넘지 않는다. 6DOF 추종 제어기(PI)는 8.0 G 주위를
오르내리며 맞추므로 순간 하중이 8 G 를 살짝 넘는 스텝이 41% 생겼다(초과량 중앙값 0.07 G, 90% 분위 0.24 G).
즉 BT-v3 가 규칙을 어긴 것이 아니라, 지령 = 한계값일 때 측정 정의가 제어기의 미세한 흔들림을 위반으로 센 것이다.

**수정.** 6DOF 에서는 "기체가 실제로 8 G 를 넘었고(0.05초 평균 Nz) 정책도 8 G 넘게 당기라고 했다(3DOF 와 같은 1차 지연을
거친 지령)"일 때만 과G 로 센다. 3DOF 에서는 두 값이 같으므로 3DOF 정의와 같다. 3DOF 결과는 바뀌지 않는다(1절 재현 시험).
코드: `dfxai/sixdof/env6dof.py`, 점검: `python -m dfxai.sixdof.overg_check`.

| 정책 (상대 BT-v2·v3 × 시드 25 × 진영 2) | 3DOF | 6DOF 옛 정의 | 6DOF 새 정의 |
|---|---|---|---|
| BT-v1 | 0 | 0 | 0 |
| BT-v3 | 0 | 0.373 | **0** |
| Shield (시드 11) | 0 | 0.149 | **0** |
| BT-v2 | 0.044 | 0.525 | 0.525 |
| RL 시드 11 | 0.046 | 0.230 | 0.229 |
| RL 시드 13 | 0.037 | 0.006 | 0.005 |

실제로 8 G 넘게 당기는 정책(BT-v2, RL)은 새 정의에서도 위반으로 잡힌다. BT-v2 가 6DOF 에서 훨씬 높은 것은 측정 문제가
아니라 6DOF 기체가 더 빨라(추력이 큼) 가용 G 가 8 G 를 넘는 시간이 길기 때문이다. 이 수정으로 10월 1일 교차검증의 과G 값
(참고 보고용)은 다시 돌리면 달라지지만, 판정 C4 는 하드덱만 썼으므로 판정은 그대로다.
**학습에 중요한 이유:** 적합도가 과G 를 벌점으로 깎으므로, 옛 정의로 6DOF 학습을 하면 정책이 8 G 대신 7.7 G 처럼 덜 당기도록 왜곡된다.

## 3. E4: 새 BT 통합

### 3.1 BT-M 연결 (손형래 전달분, 11/4)

받은 파일 `dfxai/agents/bt_manual.py`, `dfxai/experiments/validate_btm.py`, `docs/README_H1_BT-M.md`, `docs/BT-M_교범대응표.md`,
`results/btm_g1/` 를 저장소에 그대로 넣었다. **손형래의 파일은 고치지 않았다.** 연결은 다음과 같이 했다.

| 메모의 연결 제안 | 한 일 |
|---|---|
| 1. 행동 복제 교사 | `pretrain_bc --teacher btm`. 이름표가 `btm` → BT-M, `btmplus` → BT-M+ 로 부른다 |
| 2. 잔차형·게이팅형의 규칙 쪽 | 코드를 바꾸지 않고 `--bt btm` 으로 고른다(체크포인트에 기준선 이름이 저장됨) |
| 3. 감독형 | 기존 감독형이 BT-M 을 돌려 마지막 노드가 안전 노드면 그 지령을 쓴다. BT-M 은 안전 하위트리가 맨 앞이라 `safety_act()` 와 같은 결과다. 학습 정책의 G 상한은 BT-M 의 자율 제한(7.7 G)을 자동으로 읽는다(BT-v3 기반 기존 감독형은 그대로 8 G) |
| 4. 평가 조건 | `kind="bt", bt="btm"` 으로 이미 된다(별도 `btm` 종류 불필요). 학습 상대는 11/4 에 BT-M + BT-v2 로 넣었다가 11/6 에 BT-M + BT-E 로 바꿨다(3.4절, D1 확정 전 제안) |
| 형식 맞춤 | `dfxai/agents/bt_manual_adapter.py`: `SAFETY_NODES` 를 클래스 속성으로, `rule_count()`(행동 노드 수, BT-M 7개·BT-M+ 10개), 파라미터 최적화형용 `PARAM_SPEC` |

**파라미터 최적화형 상수(손형래 11/5 확인: 리드 이득 1.0–1.8, 감속 기준 속도 170–247 m/s, 나머지 6개는 제안대로).** 방어 전환 각·거리, 선회원 크기, 접근 하중, 리드 전환 거리·각, 리드 이득,
코너 플래토 상한의 8개. 안전 상수(통과 이격·하드덱·자율 G 제한)는 최적화하지 않는다. 최적화한 BT 도 기준선과 같은 안전 규칙을
지켜야 "규칙은 그대로, 상수만 조정"이 되기 때문이다. 범위는 어댑터 파일에 있다.

**수용 검사** (11/4 당시 값, 200회 반복. 11/6 재실행 결과는 3.4절): 형식 10항목과 ①②③ 은 3DOF·6DOF 모두 통과, ④ 는 3DOF 0.907 통과·6DOF 0.784 미달.
행동 복제 초기값 `results/cplan/bc/bc_btm_3dof.npz`·`bc_btm_6dof.npz` 를 200회 반복으로 새로 만들었다.
감독형 수정(G 상한) 뒤 재현 시험을 다시 돌려 모두 통과했다(기존 BT-v3 감독형 결과 그대로).

시험: 4종 학습기가 BT-M 기준선으로 2세대씩 돌고, 파라미터 최적화형 체크포인트가 BT-M 으로 다시 읽힌다. 감독형은 BT-M 교전에서
안전 노드 두 개를 실제로 발동했다(10교전 중 통과 이격 109스텝, 하드덱 회복 162스텝). 어댑터의 지령은 원본 BT-M 과 완전히 같다.

### 3.2 손형래 확인 요청에 대한 답

**① 행동 복제 R² (torch, `pretrain_bc.fit`, 300교전, 60회 반복).**

| | 손형래 (sklearn, 834회 반복) | torch 60회 (검증 스크립트 그대로) | torch 60회 (수용 검사) |
|---|---|---|---|
| 3DOF 분산 가중 R² | 0.919 | **0.861** (뱅크 0.889, 하중 0.962, 스로틀 0.657) | 0.864 |
| 6DOF 분산 가중 R² | – | – | **0.637** (뱅크 0.944, 하중 0.852, 스로틀 0.375) |

**차이는 라이브러리가 아니라 학습 횟수다.** 같은 수집 자료로 torch 를 200회 반복하면 3DOF **0.907**(뱅크 0.957, 하중 0.972,
스로틀 0.686)로 0.9 를 넘는다. 6DOF 는 200회에서 0.784(뱅크 0.955, 하중 0.861, 스로틀 0.653)다. 남는 오차는 주로 스로틀이다.
BT-M 의 스로틀 지령은 30% 와 100% 두 값뿐이라(코너 플래토 감속 규칙) 부드러운 신경망이 계단을 정확히 따라 하기 어렵다.
그래서 수용 검사와 행동 복제 초기값의 반복 횟수를 200회로 올렸다(`accept_bt --bc-epochs`). 11/6 에 기본값을 1000회로 다시 올렸다(3.4절).
④ 를 3DOF 기준(손형래 검증 스크립트와 같은 기준)으로 보면 통과, 6DOF 까지 요구하면 미달이다. 팀이 정한다.

**② 6DOF 과G 2.5% 는 추종 제어기 문제다.** BT-M 이 8 G 를 넘은 적분 스텝에서 지령은 **100% 7.7 G** 였다. 초과의 60% 가 롤 속도
60°/s 이상일 때(전체 스텝에서는 8.7%) 생겼다. 고 G 로 당긴 채 뱅크를 바꾸면(하드덱 회복의 날개 수평, 리드 턴) 롤–피치 결합으로
기체 하중이 잠깐 튄다(초과량 중앙값 +0.19 G, 90% 분위 +0.79 G, 최대 +1.3 G). G 상한을 6.5 G 로 낮춰도 0.6% 가 남은 이유다.
11/4 E3 수정(2절) 이후의 측정 정의에서는 BT-M 의 6DOF 과G 위반율이 **0** 이다(검증 스크립트 재실행 결과).
제어기 이득은 10월 1일 사전 기준에서 고정한 값이라 손대지 않았다.

**③ 하이브리드 연결:** 3.1절.

**함께 알릴 것.** BT-M 의 6DOF 교전은 95% 가 시간종료이고 격추승이 0 이다(BT-v2 상대 점수 0.465 는 대부분 무승부).
4절에서 본 "6DOF 에서는 학습 신호가 약하다"는 문제가 BT-M 출발점에서는 더 심할 수 있다. BT-M 으로 시범 학습을 다시 돌려 G2 를 판정한다.

### 3.3 새 BT 형식 (참고)

(`dfxai/agents/bt_template.py` 의 형식. BT-M 은 어댑터로 맞췄다)

1. `Policy` 를 상속하고 `act(obs)` 가 `[뱅크, 하중배수, 스로틀] ∈ [-1, 1]^3` 을 낸다. 관측은 기존 20개(`denorm(obs)` 로 물리 단위).
2. 매 `act()` 뒤 `self.last_node` 에 실행한 행동 노드 이름을 남긴다.
3. **기억이 없어야 한다**(같은 관측이면 같은 지령). D\* 가 "관측의 함수인 정책"을 전제하기 때문이다. 타이머·단계 변수 금지.
4. `SAFETY_NODES = ("…", "…")`: 감독형이 가로챌 안전 노드 이름. **하드덱 회복 노드를 꼭 넣는다**(아래 BT-v2 결과 참고).
5. `PARAM_SPEC = [(이름, 하한, 상한, 기본값), …]` 5–10개, 생성자 `__init__(self, theta=None)` (H3).
6. `rule_count()`: 논문에 쓸 규칙 수 (H5).

**수용 검사** (G1): `python -m dfxai.cplan.accept_bt --bt btm --workers 11` (이 PC 약 30분) → `results/cplan/accept_btm.md`.
형식 6가지와 H4 ①–④ 를 3DOF·6DOF 각각 판정하고, 통과하면 초기화형의 출발점(행동 복제)도 함께 만들어진다.
`--quick` 은 형식 확인용이다. 복제 정확도가 낮게 나오므로 ④ 판정에는 쓰지 않는다.

**BT-v2 로 미리 돌려 본 결과** (`results/cplan/accept_v2.md`, B안이 되면 그대로 쓰는 값):

| | 3DOF | 6DOF |
|---|---|---|
| ① 400교전 오류 | 0 | 0 |
| ② 공중충돌 / 자기 추락 | 0.090 / 0.037 | 0.055 / **0.128 (기준 5% 초과)** |
| ③ BT-v2 상대 점수 | 0.500 | 0.500 |
| ④ 행동 복제 R² (분산 가중) | 0.946 | 0.968 |

BT-v2 는 PARAM_SPEC·rule_count 가 없고, 하드덱 회복이 없어 6DOF 에서 추락이 많다. **B안(BT-v2 유지)이 되면 파라미터 최적화형을
어떻게 할지(BT-v3 구조의 기존 BTO 사용 등)와 ② 기준을 다시 정해야 한다.**

**④ 기준 보정** (3DOF, 300교전, 60회 반복): BT-v1 0.986, BT-v2 0.946, BT-v3 0.911. 노드 전환이 잦을수록 낮아진다.
0.9 는 기존 BT 가 모두 넘는 수준이지만 BT-v3 가 경계선이므로, 새 BT 가 0.85–0.9 이면 팀이 판단한다.

3. **체크포인트마다 크게 흔들리고 시드가 하나다.** +0.055 → −0.003 → +0.019 → +0.056. 구간 하한도 +0.009 로 0 에 가깝다.
   옛 규칙 시범은 40세대 유의, 50세대 미달이었다. 마지막 체크포인트가 어디에 걸리느냐에 따라 판정이 바뀔 수 있는 크기다.
4. **하드덱을 어긴 교전이 늘었다.** BT-M 은 0 인데 50세대는 교전의 18.2% 에서 한 번 이상 1,000 m 아래로 내려갔다(30·40세대는 44–47%). 침범 교전의 평균 점수는 0.610 으로
   침범하지 않은 교전의 0.424 보다 높다. 지금 규칙에서 하드덱 침범은 패가 아니고 적합도 벌점만 받는다.
   **민감도 점검으로 침범 교전을 패(0점)로 치면** 50세대 0.346, 출발점 0.398 이라 상승이 사라진다(−0.051, 구간 −0.105 ~ +0.000). BT-M(0.495)보다는 0.149 낮다.
   이것은 미리 정한 규칙이 아니라 해석용 점검이므로 G2 판정에는 쓰지 않았다. 침범이 점수를 올린 원인인지도 이 자료로는 알 수 없다.

격추는 여전히 드물다. 50세대 교전은 시간종료 92.8%, 공중충돌 4.2%, 기총 격추 3.0%이고 정책이 격추해 이긴 교전은 0.8% 다. WEZ 체류 0.34초는 BT-M 0.66초의 절반이다.
나아진 것은 HP 차이(−8.6 → −4.0)와 자기 추락(1.5% → 0)이다.

**BT-E 강도 (손형래 문의).** 학습 상대로 너무 약하지 않다. 같은 시드에서 BT-M 의 BT-E 상대 점수는 0.620 이고(수용 검사 0.635), 학습 정책의 BT-E 상대 점수는 출발점 0.550 에서 50세대 0.420 으로
떨어져 BT-M+ 와 함께 네 상대 중 가장 낮다. HP 차이도 +7.2 → −10.6 으로 나빠졌다. 지금 드러난 문제는 BT-E 가 약한 것이 아니라 학습이 BT-E 상대 성적을 잃는 것이다.

**적합도 대안.** 손형래의 조건("G2 에서도 안 오르면 K_WEZ 만 0.5 → 1.0")은 규칙상 해당하지 않는다. 다만 쓰기로 하면 K_WEZ 만 바꾸는 항목이 코드에 없어서
(`kill_first` 는 다른 가중치도 바꾼다) 새 항목을 만들어 태그 전에 넣어야 한다.

**권고.** 11/8 G2 전에 시드 1 로 같은 시범을 한 번 더 돌려 상승이 재현되는지 본다(이 PC 로 약 1시간, 명령은 `paper/C안_인수인계서.md` 4.3절).
재현되면 6DOF 학습을 진행하고, 재현되지 않으면 명세서의 실패 경로(6DOF 학습 포기 → 3DOF 학습 + 6DOF 평가)를 권한다. 판정은 팀이 한다.

## 5. E6: 분산 실행 키트

| 명령 | 누가 | 하는 일 |
|---|---|---|
| `python -m dfxai.cplan.job selftest` | 각자 | 배포 설정 그대로 2세대 → 지문(12자리)과 시험 시간. 지문은 전원 같아야 함 |
| `python -m dfxai.cplan.job queue --csv 배정표.csv --pc PC3 --name …` | 각자 | 이 PC 몫을 시드 순서대로. 꺼지면 같은 명령 → 이어서. 끝날 때마다 zip |
| `python -m dfxai.cplan.admin assign --pcs PC1:이준서:11:<시험초> …` | 이준서 | 배정표. 게이팅형 시드 N 은 초기화형 시드 N 을 돌린 PC 에 |
| `python -m dfxai.cplan.admin collect --from <드라이브 폴더>` | 이준서 | zip 풀기 + 검사(300세대 완료, 커밋 = 태그, 200세대 체크포인트, 설정 일치) |

* 학습 설정(기준선·학습 상대·σ·lr·세대 수)은 `dfxai/cplan/plan.json` 하나에 있고 태그에 고정된다. 팀원은 숫자를 치지 않는다.
* 결정성: 실행기가 numpy 를 부르기 전에 BLAS 커널(Haswell)과 SIMD 경로(AVX-512 끔)를 고정한다. 그래도 지문이 다른 PC 가
  나오면 그 PC 는 같은 시드 재현만 보장되므로, 학습은 하되 논문에 적는다.
* 축소 설정(4종 × 2시드 × 2세대, 3DOF)으로 배정 → 실행 → 재실행 시 건너뜀 → 압축·업로드 → 수집·검사 → 평가까지 끝까지 돌렸다.
  수집 검사는 커밋하지 않은 코드로 돈 결과를 "코드 수정본으로 학습"으로 정확히 걸러냈다.

**계산 시간 (중요).** 이 PC(i5-1235U 노트북, 작업자 11)에서 6DOF 1세대가 약 59초다(교전 1회 ≈ 작업자 2.4초,
명세서 가정 1.2초의 두 배). 300세대 작업 하나는 이 PC 에서 약 5시간이다. 팀원 PC 도 노트북이면 명세서의 "4–5일"보다 길어질 수
있다. **11/8 결정성 확인 때 각자 `selftest` 의 시험 시간을 받아 배정표를 실측으로 다시 만들고**, 전체가 G4(11/17) 안에
끝나지 않으면 명세서대로 10시드 × 200세대로 줄인다.

## 6. E8: 평가 파이프라인 (`python -m dfxai.cplan.evaluate all --env 6dof --workers 11`)

* 평가 대상은 모은 결과에서 자동으로 만든다: 기준선, 초기화형, 선형 혼합 α 3종, 감독형, 잔차형, 게이팅형, 파라미터 최적화형.
* 상대별 평가: 학습 상대 2 + 보류 상대(없는 BT 는 건너뜀) × 시드 100 × 진영 2. D\* 는 상대마다 진영 0 교전 20회의 궤적으로.
* 상호 대전: 유형 쌍마다 시드 N 대 N+1, N+2, 기준선은 전원과 → Bradley–Terry 레이팅(기준선 = 0).
* 결과 문서 `paper/results_cplan_6dof.md`: 유형별 학습·보류 상대 점수, 일반화 격차, 레이팅, 격추승 비율, 시간종료 의존도,
  분당 타격량, HP 차이, WEZ 체류 시간, D\*·D\*(0.90), 기준선 대비 차이. 정책별 값은 `results/cplan/eval_6dof/per_policy_b300.csv`(박윤준 Y4 분석의 입력).
* 원래 원추 재평가: 같은 평가를 3°→10° 로 한 번 더 돌린다(결과 폴더 꼬리표 `_orig`, 결과 문서 4절). 넓힌 원추의 결과가 주 결과다.
* 비용 어림(20시드, 정책 161개): 상대별 평가 약 16만 교전, 상호 대전 약 3만 교전. 이 PC 기준 6DOF 로 약 12시간이고, 원래 원추 재평가까지 하면 약 24시간이다.
  200세대 체크포인트까지 같은 방식으로 하면 약 이틀이다. 11/18–20 일정이 빠듯하므로 평가도 PC 를 나눌 준비를 한다.
